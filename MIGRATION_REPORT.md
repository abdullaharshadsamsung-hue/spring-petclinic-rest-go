### Changes from the original
- H2 and HSQLDB are no longer supported. SQLite in-memory replaces H2 as the default database. — why: There is no Go driver for HSQLDB or H2. SQLite takes over the in-memory dev and test role, and Postgres is the production target.
- MySQL support is dropped for now. The mysql profile and DDL are not carried over. — why: Deferred. Adding it later only needs a third dialect folder, because SQL already uses ? placeholders. db/mysql/schema.sql is the source when that happens.
- The jdbc, jpa and spring-data-jpa profiles are gone. There is a single database/sql repository implementation that follows default spring-data-jpa semantics. — why: These were alternate implementations of the same interfaces chosen by Spring profile. Go gets one implementation.
- The Postgres schema uses named CREATE INDEX IF NOT EXISTS indexes instead of unnamed CREATE INDEX. — why: The source's unnamed CREATE INDEX creates a new duplicate index on every boot.
- page/size out of range on the v2 endpoints returns a 400 validation problem instead of 500. — why: The spec documents 400, and the 500 was accidental (ConstraintViolationException hit the catch-all).
- An unknown route returns a 404 problem (title NoResourceFoundException) instead of 500. — why: Listed in the plan as a deliberate deviation. The source's NoResourceFoundException fell into the catch-all handler.
- A role denial with security on returns a 403 problem instead of 500. — why: A security failure must not look like a server error.
- POST /specialties, /vets and /visits with an id in the body always insert a new row and return the generated id. — why: JDBC updated a nonexistent row and returned the fake id, and JPA merge behaviour varied. Always inserting is consistent.
- A visit created via VisitFields without a date defaults to today instead of failing with a 404 integrity problem. — why: This matches the intent of the entity's constructor, which defaults the date to today.
- An owner telephone that is spec-valid but not exactly 10 digits gives a 400 validation problem instead of 500. — why: The service-level Validate() replaces JPA pre-persist validation, which threw a 500.
- The lastName search is always case-sensitive. On HSQLDB the original was case-insensitive. — why: This matches H2 (the source default) and Postgres behaviour.
- 204 update responses carry headers only and no body. — why: Go's net/http forbids a body on 204. Spring's body was dropped by the container anyway.
- The /oops endpoint is removed from the router and from the served OpenAPI spec. — why: It had no controller in the source.
- The H2 web console (/h2-console) is no longer available. — why: It is dev tooling only, and H2 is not used. A JVM-only database console has no Go counterpart (inferred).
- Swagger UI is an embedded HTML shell that loads swagger-ui-dist, instead of springdoc's bundled UI. — why: springdoc is Spring-specific. The spec is served from the embedded openapi.yml.
- Spring cache starter and the CallMonitoringAspect are not migrated. — why: No @Cacheable exists, and the aspect was never registered, so neither was active in the source.
